# DNS-сервис

Небольшой сервис на FastAPI, который хранит A-записи DNS: каждому доменному имени
соответствует один IPv4-адрес. Список записей и адрес по имени доступны всем; создавать,
менять IP и удалять записи можно только с ключом администратора.

Подходит небольшим командам и учебным стендам как простой справочник
«имя -> адрес» для своих машин.

Данные хранятся в памяти процесса и сбрасываются при перезапуске.

## Маршруты

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/` | все | Приветствие и ссылка на документацию |
| GET | `/health` | все | Проверка работоспособности |
| GET | `/version` | все | Версия приложения |
| GET | `/records` | все | Список всех A-записей |
| GET | `/records/{name}` | все | Адрес для домена (404, если записи нет) |
| POST | `/records` | ключ | Создать запись `{"name", "ip"}` (409, если запись для домена уже есть) |
| PATCH | `/records/{name}` | ключ | Обновить IP записи `{"ip"}` (404, если записи нет) |
| DELETE | `/records/{name}` | ключ | Удалить запись (404, если записи нет) |

Доменное имя проверяется и приводится к нижнему регистру (точка в конце отбрасывается):
не меньше двух меток, метки из `a-z`, `0-9` и `-` длиной до 63 символов, без дефиса в
начале и конце, всё имя до 253 символов. Адрес должен быть корректным IPv4
(`192.0.2.10`). Если имя или адрес некорректны, сервис отвечает `422`.

Примеры:

```bash
curl -X POST http://127.0.0.1:8000/records \
  -H "X-Admin-Key: $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "example.com", "ip": "192.0.2.10"}'

curl http://127.0.0.1:8000/records/example.com
curl http://127.0.0.1:8000/records

curl -X PATCH http://127.0.0.1:8000/records/example.com \
  -H "X-Admin-Key: $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"ip": "198.51.100.7"}'

curl -X DELETE http://127.0.0.1:8000/records/example.com -H "X-Admin-Key: $ADMIN_KEY"
```

Без заголовка `X-Admin-Key` создание, изменение и удаление отвечают 401, с неверным
ключом 403. Если `ADMIN_KEY` не задан, изменять записи нельзя совсем.

## Подготовка окружения

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt   # для тестов
cp .env.example .env             # Windows: copy .env.example .env
```

## Запуск

Для разработки (с автоперезагрузкой):

```bash
python -m uvicorn app_final:app --reload
```

Для обычной работы:

```bash
python -m uvicorn app_final:app --host 0.0.0.0 --port 8000
```

После запуска:

- приложение: http://127.0.0.1:8000
- документация: http://127.0.0.1:8000/docs

## Тесты

```bash
python -m pytest -v
```

Тесты также запускаются в GitHub Actions при каждом push и pull request; после
успешных тестов workflow сохраняет artifact `dns-service` с файлами приложения.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `DNS-сервис` | Название сервиса |
| `APP_VERSION` | `1.0.0` | Версия, которую отдаёт `/version` |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG`, `INFO`, `WARNING`) |
| `ADMIN_KEY` | пусто | Ключ администратора для создания, изменения и удаления записей |

Значения читаются из окружения или из файла `.env`. Файл `.env` не коммитится;
в репозитории лежит только безопасный пример `.env.example`.

## Диагностика

Проверка, что сервис жив, и его версия:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
```

Логи выводятся в консоль, где запущен uvicorn: запуск с настройками, каждая строка
запроса (метод, путь, код ответа, время), создание, изменение и удаление записей,
конфликты и отказы в доступе. Сам ключ в логи не попадает. Для подробных логов задайте
`LOG_LEVEL=DEBUG`.

Частые проблемы:

- `401`/`403` при создании, изменении или удалении: не передан или неверен заголовок
  `X-Admin-Key`, либо не задан `ADMIN_KEY`;
- `422`: недопустимое доменное имя или IPv4-адрес;
- `409`: запись для этого домена уже есть (сначала удалите её);
- `404`: записи для домена нет;
- после перезапуска записи пропали: данные хранятся только в памяти.
